# Community completion API

`progress/beta.ts` uses registered `KEYS.betaCompletions` (`punchies:beta-completions:v1`, transformed by the edition/staging namespace). The key is present and preloaded only for `itchbeta`; its save list has 12 keys while Master and CrazyGames retain 11. No historical unregistered community key is imported. It has no normal progression, XP, title, currency, shop, chest or grant side effects. `betaView()` gives completed count, wins, lightweight records `{id,mode,win}` and milestone state; `betaFighters()` returns Marco/Mia/Bruno initially, Roxy at 3 and Nadia at 5. Build owns availability filtering and default-skin-only UI.

Build callers allocate `newBetaCompletionId()` once when creating a whole match/series and carry the ID through all BO3 round restarts. Call `recordBetaCompletion` only at a confirmed terminal whole-series outcome, with mode `ai`, `local` or `online`, completed/seriesComplete true, and explicit forfeit/disconnected/qa false. Win or loss counts. A duplicate ID does not count twice. Intermediate rounds, Survival, tutorial and training are excluded. For online, use the peer-agreed series identity if available, not a new ID at each KO or reconnect. Rejected outcomes and storage failure return false.

No gameplay caller is installed by this change: Build owns edition flags and wiring real terminal outcomes. Existing normal progression remains untouched. The ledger is local storage through the existing portal store and therefore is not a secure server achievement or cross-device account entitlement.

Existing version-1 `ids` remain completion history even when records are absent. Wins count only valid new recorded wins; missing historical win data is never invented. Repeated IDs cannot upgrade or rewrite historical outcomes. Build owns the match/win UI copy and will request any new localisation keys before production.
