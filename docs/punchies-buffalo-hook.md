# Tyke SUPER: Buffalo Hook staging prototype

`fighterSuper('tyke')` returns id buffalo-hook, mechanic hook, closed name/description keys and existing starCost4. Gameplay input/save/tune action remains uppercut. Other fighters retain their approved abilities.

Activation spends the existing Tyke SUPER stars/stamina once and starts a standard Hook pose/geometry/timing with an explicit base20 damage. Standard Hook quality, head/body, fatigue, buff, emergency, counter, stun, push and guard chip rules still apply once. The explicit base is not multiplied by Tyke's old Rising Upper override/reference-cost formula. Only actual unblocked HP loss confirms the follow-up; sweet or damaging sour qualifies. Guard/Perfect Guard chip, zero-damage sour body contact, zero-HP training targets, dodge and whiff do not. Misses receive no implicit refund.

After the same tick's simultaneous contact batch, before timers advance, the confirmed Hook becomes one Upper at frame0. This preserves crowd Hook contacts as Hook rather than processing stale contacts with new Upper properties. The Upper points once toward the first confirmed target's actual position, without teleporting either boxer. Standard visible Upper startup, reach, sweet/sour windows and recovery remain; normal timers advance it like every other punch. It can miss or be dodged and cannot deal invisible immediate damage.

The follow-up's explicit base30 applies quality, activation dodge buff, current emergency and contact counter once. Standard Upper has no Hook fatigue, so Hook fatigue is not incorrectly carried into the Upper. Both normal Guard and Perfect Guard are bypassed, as explicitly approved for this unique move. There is no second resource charge or star gain. Startup/meter-stun interruption remains normal; if the initial Hook is cancelled during the simultaneous contact batch, the follow-up does not survive the cancellation. Initial target death is safe; no damage is forced against a dead/out-of-range target.

`PunchState` carries buffaloActivation/baseDamage, a single buffaloConfirm target snapshot, and buffaloUpper on the follow-up. Contacts retain their source PunchState identity, preventing stale Hook contacts becoming Upper contacts. Survival flushes once after all contacts and starts a fresh Upper swingHits ledger, so targets can be hit once in each genuine phase. Event buffaloFollowup {attacker,targetId,x,y}, plus existing Hook hit/throw and Upper throw/hit events, supplies the visual/audio phase change. No new AI entities or assets are fabricated.

Explicit20/30 data lives in super-config.json, not the obsolete Rising Upper damage scalar in tune.json. The compatibility fingerprint includes those simulation-only fields and the new ability ID; name/description localization does not change rules. Staging should include the separate compatibility gate before enabling online play; offline-only staging is a Main decision. No Worker/frontend/itch publish from Logic.

Focused tests cover exact20/30 bases, each multiplier once, huge legacy override/reference-cost changes having no effect, cost4/resources once, sweet/sour/blocked/chip/zero-HP/dodge/whiff confirmation, both-guard bypass, visible startup/range, one chain, original crowd contact identity/fresh ledger, applied damage totals, deterministic replay and delayed-input rollback/hash. The two-target crowd fixture disables separation only to exercise simultaneous contact ordering, then restores it; it is not a default-spacing balance claim. Existing CODE X/Super/Survival/type/localization checks pass. Standard Hook push and the visible Upper startup can create a dodge/spacing escape; no range or push buffs were invented to guarantee the combo.

Art owns the finite typed three-ability name/description display route; VFX owns any unique presentation beyond the existing standard Hook/Upper effects. New name/description are translated in all six local JSON files; native Sheet alignment must accompany the selected Super staging batch, not the shop-only hotfix.
